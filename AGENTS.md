## Repository map

- `src/`: shared compiler, persona adapters, CLI, local editor, and MCP server.
- `src/muse-handoff.js`: browser-safe builder for all 18 named presets. Returns the exact message, encoded URL, recipe version and public reference metadata; `scripts/build-web.js` copies it into `dist/core`.
- `src/muse-wigs.js`: canonical costume, hairstyle and visual recipe for the 12 wig presets, shared by native trials and the combo builder. Keep its built browser copy current.
- `src/muse-costume-recipes.js`: canonical hairless costume recipes for Harry Potter, Michael Jackson and Joker; shared by native trials, combo construction and the text-only fallback. Copy this module into the browser build too.
- `web/`: static website and committed avatar assets.
- `characters/catalog.js`: personalities and authored sample replies; `characters/avatar-design.js`: the versioned shared base, costumes, and Muse avatar prompts.
- `characters/image-generation.json`: original art prompts and generation outcomes. Preserve refusal history and superseded attempts. Active costume replacements must identify the same preset, shared base, and design version as the catalog. `characters/avatar-design-generation.json` records the shared reference's provenance.
- `scripts/`: website build and local preview.
- `test/`: Node test suite. `dist/` is generated and must stay untracked.

## Development and verification

Use Node 20 or newer and `npm ci`. For website work, run `npm run build:web`, `node --check web/app.js`, `node --check web/spotlight.js`, and `npm run preview:web`; the preview is at `http://127.0.0.1:4173` and needs a rebuild after changes.

Run `npm test` when compiler, build, or other tested behavior changes. Add focused regression tests for actual failure modes. Check affected browser flows at desktop and mobile widths, including missing or failed images when touching avatar rendering. Run `git diff --check` before committing. The existing CI primarily covers the Node suite and package installation; report browser checks separately.

## Implementation rules

- Reuse the compiler in the browser; do not duplicate trait-to-prompt logic. Keep its imports free of Node-only dependencies.
- Handoff links, complete-combo clipboard fallback, displayed instructions and JSON export must use the same builder with the current tone. Retain `museAvatar.prompt` as labeled text-only data matching the active costume/hairstyle; exports also include the complete `comboPrompt`, `museHandoff`, applicable hairstyle/variant fields and curated-preview metadata. Export `costumeVariant` for the three new hairless costumes and keep preview provenance independent of whether a hairstyle exists. Do not substitute the text-only prompt for the reference-based fallback.
- Use real links for primary Muse navigation on the stage, tiles and detail dialog. Keep their URLs current after tone edits/reset and saved-state changes, preserving tile nodes and focus. Keep optional setup controls separate. An existing Muse draft may prevent prefill; explain clear-and-reopen or complete-combo copy without promising automatic submission.
- Preserve authored emoji preferences when switching presets. The compiler omits the neutral `sparing` phrase, so the handoff wrapper explicitly permits sparing emoji for Barbie/SpongeBob and replaces old no-emoji preferences. Do not impose the original trio's no-emoji wrapper on every preset. Verify persistence separately from wording or platform reactions.
- For native handoff validation, record exact prefill, reference activity, chooser completion, every option, latency, saved-style transitions and restoration separately. Keep the original selected avatar unless activation is part of the task. Preserve private account evidence outside Git, and do not treat visible unchanged profile text as a full memory audit. The release matrix intentionally takes no Select actions.
- Examples are authored samples, not live model responses. Saved combos are browser-local; downloads do not imply import or cloud sync.
- Keep art files inside `web/avatars/` and provenance in the character manifest. Copy selected native WebPs unchanged, retain their output hashes and archive superseded replacements. The three retained PNGs and shared base keep their existing paths; preserve superseded PNG costumes as history when a native preview replaces them. Never claim a failed generation produced an image or relabel an unrelated preview as the requested likeness.
- Validate asset references during the build and handle image failures in the UI. Preserve character access and prompt copying even when a preview is unavailable.
- Keep changes scoped, preserve dependency versions unless needed, and never commit credentials or generated deployment archives.
